# 验收范围

中文 | [English](validation.en.md)

本记录对应 0.4.1，目标宿主 DeepSeek Harness 0.2.1-rc.5，电脑端为 Apple Silicon Mac、macOS 13 及以上。Release notes 记录最终提交、安装包 SHA-256 与公开下载复验结果。

## 0.4.1 功能与制品检查

18 项项目检查覆盖认证、权限、独占连接、信令／输入隔离、旧连接清理、缩放坐标、显示器与画质参数白名单、显示器不存在时拒绝连接、唤醒顺序、取消清理，以及高频移动／滚动合并和可靠松键。

两种画质模式保留显示器独立选择：流畅优先最高 1440p、优先保持帧率；清晰优先原生像素最高 3840×2160、优先保持分辨率。手动分辨率字段已从网页及连接 API 移除，升级后必须重新加载旧页面。

本地 0.4.1 安装包已在隔离 DSH profile 验证真实 Loader、所有者登录、网页资源、受保护 API、卸载后 404 和重装恢复。正式 Mac 已安装并启用，29 个安装文件与该本地包一致，Host 未重启。公开发布会从固定提交重新打包，再单独验证正式附件；同一版本号不代表文档和制品字节相同。

## 实际设备与浏览器结果

- 既有版本已收到真实桌面视频；中文、特殊字符、合成测试密码和鼠标点击由 Mac 测试窗口确认。手机用户已确认连接、操作、断开、双指缩放。
- 0.4.0 的两块实际显示器四档采集尺寸均通过核对。用户随后确认手机清晰度改善，内置和外接显示器都能操作。
- 0.4.1 Chrome 实际收到清晰优先 2940×1912、流畅优先 2214×1440，两种模式自动重连成功。390 CSS px 无横向溢出，只展示两种画质模式。
- 用户报告旧版 4K 约有 1 秒跟随延迟、1440p 稍好；随后确认 0.4.1 流畅优先明显改善、已可正常使用。清晰优先在手机原网络下的延迟未单独确认。
- 浏览器归类为微信或其他应用内浏览器；具体手机机型和网络未记录。390×844、820×1180 的布局检查属于浏览器模拟，不能代替真实 iPad 验收。

## 延迟优化的证据边界

同一限速输入重放中，旧版积压 65596 字节并丢弃鼠标松开；新版合并为最后位置后可靠松开，积压为 134 字节。按模拟 32KB/s 计算的队尾等待约为 2002ms 和 4ms。这是传输队列重放，不是手机端到端延迟。

本机浏览器样本的清晰／流畅模式约为 29／30 FPS、69／22ms 视频接收缓冲、4／1ms 网络往返。这些样本不代表相同手机网络，也不是点击到画面的完整延迟对比。采集队列为两帧，超过 150ms 的旧采集帧不再提交编码；这不构成端到端延迟上限保证。

## 未验证与已知限制

真实 iPad、各浏览器和不同网络、TURN 中继、整机睡眠唤醒、锁屏密码输入与解锁、系统特殊安全输入仍待单独验收。普通密码框成功不代表 Touch ID 或 FileVault 解锁可用。显示器休眠故障曾在锁屏 Mac 复现，唤醒后采集启动恢复；不能据此认定锁屏画面和密码输入可用。原生助手为临时签名，未做 Apple 公证，每台 Mac 需要单独完成权限授权。

Desktop 热更新曾使侧栏入口未恢复，Host 组件仍运行、手机原链接可用。未为此重启整个应用，入口在正常重启后的恢复尚未确认。本版不支持 Intel Mac、Windows、Linux、音频或文件传输。
