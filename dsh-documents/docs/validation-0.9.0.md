# 0.9.0 验收

[English](validation-0.9.0.en.md)

日期：2026-11-04。DSH 0.2.1-rc.5，macOS arm64。项目使用 Node 24.16.0、pnpm 10.33.2；未新增依赖，插件锁文件与本轮开始时逐字一致。正式 Desktop 经官方任务检查正常退出后安装，重启生效。GitHub 发布沿用相同运行文件，仅更新面向读者的说明和验收记录。

## 覆盖

- 115 项行为检查通过。包含会话路径与地址编码、完整读取、大小/编码限制、BOM/CRLF、原子版本保护、只读与冷会话权限、越界和符号链接、恢复副本与开关生命周期；0 失败、0 跳过。
- 独立 DSH_HOME 中通过真实 Loader 和安装包运行，官方文件树打开 Markdown 后显示「文档库编辑器」；普通文本仍走官方查看方式。关闭设置后 Markdown 恢复官方预览；无需配置文档库根目录或 Inbox 即可保存此开关。
- 原生 Chrome 使用真实系统拼音：组合、退格修正、空格提交、Tab 新增行及移动焦点、Shift+Tab 返回、Escape 回正文通过。未提交拼音不进入原文件或宿主恢复副本；“你好”逐字回读且只出现一次。英文输入法未生效的尝试不计中文通过。
- 实际切换会话为只读后，编辑 DOM 为不可编辑，点击表格不会产生输入框；保存端同样拒绝写入。重启后对冷会话读取精确权限投影并成功保存，无需发消息或启动模型。
- 实际 RPC 拒绝过期版本，保留外部修改；保存和恢复后 frontmatter 原始前缀保留。
- 文档大纲能显示标题并定位，文档内查找选中正确文本。其他格式沿用官方注册与打开方式，未禁用文件树、预览框架或工作区模块。
- 真实停服后输入，原文件保持旧内容，UI 暂停保存。宿主重启、客户端页面重载后，从浏览器恢复入口找回未到达宿主恢复目录的“断线恢复终验”；手动恢复后自动保存，原文逐字回读一次。

## 断线问题与修正

最初恢复副本仅写宿主。停服时副本请求也失败，客户端重建后单纯内存缓冲不够。先让“失败写入 → 编辑器结束 → 新恢复读取器”的回归检查失败，再增加异步 IndexedDB 副本并复跑原场景。恢复写入仍由共享 AutoSave 的已提交输入门控触发；按空闲节奏备份，合并重复快照，未在每次按键时同步写存储。宿主与浏览器的同一草稿用写入序号比较新旧，不以跨机器墙上时钟决定正文。

浏览器和宿主副本分别受容量限制，不自动淘汰待恢复草稿。任一副本不可用时显示相应状态；正文保存仍使用宿主版本校验。原文件已变化时恢复内容暂停自动保存，用户可复制或放弃草稿后重读。

## 证据边界

实际运行包括本机 DSH 服务和 Chrome 页面，断线通过停止临时服务复现。不同执行环境的路径、版本与权限通过文件系统契约夹具覆盖；没有连接异地 SSH 主机，不将其写为异地主机实测。宿主重启后的当前客户端可能需要刷新页面，浏览器草稿恢复已覆盖页面重载；未修改宿主的重连实现。

不把构建、安装、回归脚本或 EditorState 耗时称为端到端物理按键延迟。正式 Desktop 0.9.0 已从官方文件树验证共享编辑器、表格编辑、Tab 换格和自动保存，原文回读标记一次且属性前缀保留；关闭开关恢复官方 Markdown。普通文本回退的 Desktop 取样在开关关闭时完成，Web 在开关开启时完成，两者分别记录。真实跨机器设备与不同输入法仍需各自验收。原目录、Inbox 和随记配置保留，正式笔记、Inbox 和全局随记草稿未修改；测试后默认 Markdown 开关恢复关闭。

用户已明确暂缓新增 IndexedDB 恢复副本与真实系统候选的联合实测，本轮不再以此阻塞交付。组合输入期间不备份及提交后备份已由共享 AutoSave 的回归检查覆盖；这项联合实测未执行，不计为通过。
